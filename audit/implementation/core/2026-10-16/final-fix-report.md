## Early registration API for subsequent implementers

`CausalPredictor.fit(self, request: FitRequest, *, on_run_created=None)` calls `on_run_created(paths, metadata)` synchronously after run creation, assigning `self.run_paths`, and preparing full growth metadata, but before `fit_parent`/`continue_fit`. The metadata includes `causal_adapter = {method_id, recipe}`. For continuation it is copied into both live growth metadata and existing selected-best metadata before continuing; this avoids recovery selecting a checkpoint with a different immutable growth hash. Fresh fits pass it through `fit_parent(data, config, paths, *, growth_metadata: dict | None = None)`, which copies it into the new state before initial observation and `_run`/checkpoint publication. The default generic training API remains backward compatible.

The paired runner's coordinator-owned `register_child(run, record, name, stage_index, metadata, parent_id=None, allocation=None)` makes the run visible (`open_child`), appends an unavailable-until-return stage record, publishes `child_registered`, and calls `observe_child` for already known context. Direct parent fit registers `{}` metadata immediately after `create_run`. On success `_stage_record` replaces that pending stage with observed event-derived information. On failure the training API terminalizes the child; the coordinator retains linkage without attempting prohibited terminal observation mutation. A callback is a registration hook, not a request to mutate scientific metadata. The owning coordinator must handle any callback/publication exception and must create independent attempts rather than reopen terminal children. Future B6 callers should register each probe before training and preserve canonical-parent copying and their own distinct method recipe; B6 itself is outside this patch.
