## Interfaces and evidence boundaries

`treeneuron.evaluation.confirm.prepare_cohort(design, sources, output, *, cohort_id, root_seed) -> dict` revalidates the numeric design, creates fresh immutable teacher specifications, F-only target arrays, complete F/G/V arrays, and T row-ID commitments. It returns a fresh sources mapping for versioned `publish_design`; old sources are not mutated. It never fits or generates T inputs/labels. The optional `development` repository-relative path/hash reference extends each strict unit schema and is checked against frozen manifest identities/hashes. Legacy units without that key remain readable by protocol validation but cannot enter actual fitting without the retained development inputs.

`run_confirmation(protocol: FrozenProtocol, study: str) -> Path` validates the frozen source/design, enforces actual CPU runtime preflight, and serially executes the declared fixed unit/repetition inventory. All eight roles use the extracted actual Task 8 fitting graph. Failures retain the same run/unit/seed and their attempt/resource/exception records. Registered selected models are immutable; incomplete protected label access cannot be retried or replaced. Completed evaluations are reloaded from sealed evidence. Main invocation and nested fitting clocks are separately identified; forecasting uses the frozen design.

`fit_repetition(config, data, root, recipe_hash)` in `pilot/calibrate.py` accepts development data only and preserves the existing shared parent, checkpoint/stage/sampler/allocation/contrast, B6 coordinator/loser graph, fresh ordinary/static controls and allowances. It saves all eight actual CausalPredictor checkpoints. `run_repetition` remains the exploratory E wrapper and retains its previous report fields/graph and E output. No generic fitting API receives T labels.

`load_predictors` validates and loads registered actual saved checkpoints. `audit_models` compares each saved model's metadata and exact weights to its role's final G-selected checkpoint, in addition to the inherited full graph audit. Model references are converted to strict repository-relative path/hash objects before registration.

`aggregate_teachers(predictions, runs)` rebuilds regression risks from raw saved targets/predictions and original F population variance. Identical run IDs deduplicate; conflicting identities reject. Missing or invalid paired repetitions leave the teacher present with no zero-filled effect. Optimizer/allocation repetitions average within teacher/data units before calculating `D = R_random - R_top`; positive D favors scored placement. Unnormalized effects, normalized-risk degeneracy, scalar group/tail/noise-free metrics and regime slices remain explicit.

`analyze_primary(study_dir, protocol)` reloads authorized sealed evidence, checks declared cohort/graph/model identities, reconstructs all metrics, and writes content-addressed immutable `primary-<hash>.json` reports. It reports teacher-level mean, median/full effects, reproducible percentile bootstrap, Student-t sensitivity, counts and declared optional Holm families. Singleton/zero-variance/incomplete/unsupported/MC-unresolved cases cannot produce completed-cohort superiority. Placement evidence does not establish practical advantage.

CLI: `prepare-cohort --design PATH --output PATH --cohort-id ID --root-seed N --publish NEW.md`; `confirm --protocol PATH --study synthetic`; `analyze-primary --protocol PATH --study-dir PATH`. Preparation precedes the actual freeze and does not create a circular frozen-protocol prerequisite.

## Final integration refinements

The optional cohort `preparation` reference binds a strict v1 receipt to the complete unit list and source raw-design hash. It retains measured preparation seconds/bytes and an explicit boundary. Legacy cohorts without it report null preparation and combined cost, never zero. Confirmation storage includes preparation, fitting and protected evidence as distinct file paths; runtime comparison combines only disjoint preparation and active-invocation clocks. Hard process interruptions retain an unknown-duration marker, including stops between atomic units. Analysis writes separate immutable `analysis-work/<uuid>.json` receipts linked to the deterministic report hash and includes the cumulative disjoint analysis cost only when preparation/execution measurements are available. These timings are fixture machinery verification, not scientific cost measurements.

Pre-label prediction failures retry only the already registered models and original run within the frozen count. Sealed evidence read failures stop rather than repeatedly attempting to repair immutable evidence. Resume after sealed completion never re-predicts or regenerates labels. The exact frozen evaluation order is enforced even when JSON canonicalization or a caller reorders model/callback mappings.

Reanalysis verifies not only selected-model/graph correspondence but exact frozen run/unit/protocol/nominal-and-effective-seed provenance, actual retained teacher/development hashes, parent model/training/growth/data/seeds, and registered model references. A self-consistent local pair/ledger edit changing the optimizer provenance is retained as invalid and cannot yield a valid teacher. Explicit descriptive H2 contrasts include ordinary-upper minus static-partial and ordinary-upper minus warm-widened-upper, in addition to each anchor versus top. Their superiority fields remain false absent a separately explicit frozen inferential family.

## Concrete Task 13 storage/schema handoff

All repository file references remain exactly `{path, sha256}`; absolute original-root and process-relative child locators below are intentionally exposed for Task 13, not silently normalized around the source gate.

- Prepared output: `OUTPUT/unit-N/{teacher.json,F.npy,development.npz,commitment.json}`, plus `OUTPUT/{preparation.json,sources.json}`. A unit contains `unit_id, seeds, teacher, fit_targets, development, manifest, run_ids`; `development` is an optional compatibility extension but required by actual fitting. NPZ keys are exactly `F/G/V` × `X/y/row_id/group_id`. Cohort contains `study_id, cohort_id, root_seed, units` and optional bound `preparation` reference. Preparation receipt v1 keys: `schema_version, units_sha256, raw_sha256, seconds, retained_bytes, boundary`; `units_sha256` hashes the mapping `{"units": units}`. New preparation explicitly supplies scientific `confirmation_policy` v1 (`schema_version, gate_threshold, regime_slices, regime_claim, holm_families`).
- Confirmation root: `PROTOCOL_PARENT/confirmation/PROTOCOL_HASH/`. `confirmation.json` v1 contains `schema_version, protocol_hash, study, seed_policy, status, runs, invocations, costs`, with optional `unmeasured_interruption`. The `runs` list is exactly the frozen unit/repetition order. Run entries contain `unit_id, run_id, repetition, status, attempts`; completed runs add a strict `predictions` reference. Failures can add `reason`.
- Fitting attempts: `CONFIRMATION_ROOT/RUN_ID/attempt-N/`. Attempt entries contain `index, status, seconds, phase, path`, later `pair` ref and `peak_rss_bytes`; failures add `error, resource_limited`, and unknown hard-stop durations add `duration_incomplete`. `phase` is `fitting_and_evaluation` or `evaluation`. An inference-only retry reuses the original fitting `path` and `pair`; do not assume a new numerical fitting directory for every attempt. Recovery of an already sealed result reuses the declared run and original selected model linkage.
- `pair.json` retains the existing Task 8 graph (`child_runs`, shared parent identity/checkpoint, `methods` and their stage-relative paths/events, `greedy_report`, allocations, pairing audit, capacity, nested clocks), and adds actual `models` refs plus `confirmation={protocol_hash, unit_id, run_id, nominal_optimizer_seed, effective_seeds, seed_policy}`. `models/ROLE.json` pointers reference their versioned metadata/tensor payload siblings. Top-level child/B6 locators retain the producer's absolute/process-relative forms; stage locators are pair-relative. `_validate_pilot_graph` and `audit_models` are the current consumers. Their strict live source/lock/runtime validation must remain binding for ordinary execution.
- Protected evidence: `PROTOCOL_PARENT/access/PROTOCOL_HASH/access.jsonl` is the original hash-chained lifecycle ledger. Each `runs/RUN_ID/link.json` binds protocol/study/unit/run/manifest/F variance and all eight model refs. `runs/RUN_ID/predictions.json` contains `protocol_hash, run_id, row_id, metrics, predictions, observations`; observations contain `y, noise_free_target, group_id, regime_masks`. Only `load_evaluation` should expose sealed observations after the original access/completion/output-hash checks. The optional confirmation ledger prediction ref does not replace this authority.
- Deterministic reports: `CONFIRMATION_ROOT/primary-REPORT_SHA256.json` (schema v1) contains declared/valid teacher and run counts, per-teacher effects/metrics/regimes/status/errors, reconstructed run records, primary mean/median/full effects/intervals/precision status, descriptive controls, explicit-family Holm adjustment, forecast/cost snapshot and interpretation. Null effects stay null. `report_sha256` hashes the report before adding that field. No ordinary repeat overwrites a report; changed incomplete inputs produce a new hash/version.
- Work evidence: `CONFIRMATION_ROOT/analysis-work/UUID.json` v1 contains `schema_version, protocol_hash, report_sha256, seconds, previous_analysis_seconds, total_study_work_seconds, total_reason, boundary, aggregation`. These non-deterministic timing receipts are separate from deterministic scientific output. `costs.seconds` is active confirmation invocation work; `preparation_seconds` and `combined_seconds` can be null. Combined time and forecast deviation remain null for absent preparation measurements or hard-interruption duration. Nested child clocks are never summed into the enclosing total. Reanalysis time is separate from the frozen fit/evaluation forecast.
