## Changes and contract boundaries

**I1 — failed/interrupted evidence.** Every caught failed/interrupted attempt records a strict `retained` inventory with fields `schema_version=1`, `state`, `files`, `protected_files`, `reason`. `files` is the exact relative-path→SHA256 map of all materialized attempt bytes. `protected_files` records already observed link/prediction bytes in that run's protected directory; later inference-only publication may add files, but existing observed bytes cannot change or disappear. Live auditing validates the inventory, partial child registrations/manifests/config identity, explicit cost terms, available best/last checkpoints through the ordinary strict loader, and recorded parameter counts. Failed attempts need not contain a complete successful role graph.

States are `captured`, `not_materialized`, `unknown_hard_stop`, and producer-side `unknown_capture_failure`. Honest failure before creating an attempt directory has an empty `not_materialized` inventory. Hard-stop recovery records only post-stop observed bytes, keeps duration `null` with an explicit incomplete-duration classification, and cannot attest the earlier inventory. Capture errors fail closed. A completed recovered run retains its earlier unknown marker; ordinary load/resume does not erase it. `accounting.retention` exposes the status and affected attempt IDs. Unknown historical retention prevents a fully verified/completed audit claim, while retaining usable primary rows and numerical summaries. Structurally valid incomplete evidence may still be sealed; unknown retention remains in the immutable live audit, manifest and archived result. Missing/corrupt declared bytes block sealing.

Archived analysis verifies the exact copied inventory and partial JSON/cost evidence but never loads historical checkpoints with the current execution package. The original live validation attests those checkpoints. The private accounting switch is used only after archive inventory verification; it does not create a live protocol, evaluator, model, resume or training capability.

**I2 — actual receipt I/O.** Both `pilot.calibrate._runtime_preflight` and `fit_repetition` resolve the frozen backend receipt locator through `locate(..., producer=True)`. The train consumer `_backend_evidence` resolves the configured receipt at the same boundary. This supports absolute original-root locators and relative locators in a faithful relocation, while retaining the exact frozen config/hash and ordinary numerical receipt checks. Numerical producer and lock files are unchanged. The test invokes real preflight and actual eight-role tiny fitting in fresh subprocesses with the original root unavailable, then terminal reopening with the real preflight and a deliberately corrupt receipt rejection. Only terminal protocol construction is substituted in that bounded path test; preflight/path validation is not bypassed.

**I3 — executing analysis identity.** `_analysis_identity` first obtains the ordinary strict clean execution snapshot, then compares its entire `src/treeneuron/**/*.py` path/hash map against the package source actually imported by the interpreter. A clean unrelated repository or different clean committed package rejects. A faithful equal-source installed/relocated copy accepts. `analysis_root` remains a locator, not an authority override. Tests use committed actual package copies rather than a stubbed source validator.

**I4 — completion and archive eligibility.** Normal terminal confirmation writes immutable `archive-completion.json`, binding the protocol hash, exact terminal ledger SHA256 and terminal status to explicit `unsealed` eligibility and a reason. A no-op terminal reopening validates this receipt without rewriting the ledger. After copying and verifying a prospective archive, `seal_archive` writes a separate digest-named immutable `archive-bindings/<canonical-hash>.json`; the original frozen protocol, history, terminal ledger and initial completion receipt stay unchanged. New receipts contain exactly `schema_version`, `protocol_hash`, `confirmation_sha256`, `archive_sha256`, `scope`, `path`, `reason`.

Repository-local bindings use `scope=repo_local` and a repository-relative archive-manifest path. Live audit revalidates the manifest, exact copied inventory and original protocol/terminal ledger identity. External seals use `scope=external_unbound`, `path=null` and an explicit saved-only selection reason; they never imply an automatically portable live binding. `archive_eligibility` is exposed by live audit and deterministic report rendering (`unsealed`, `external_unbound`, `bound`). No recursive audit↔seal validation occurs: a binding reads and validates the existing immutable archive directly. Archive copy work now includes verification and binding; the final work-receipt write is explicitly excluded. Confirmation timing explicitly excludes its final ledger/completion-receipt writes.

Repository-local bundles also exercised nested-root relocation: the scoped locator is idempotent for paths already in the current root, and archive roots are normalized before path comparisons. Neither adjustment relaxes containment or source/receipt validation.
