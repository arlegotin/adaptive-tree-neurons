Any continued training must use its exact original source/lock/runtime or start a new correctly identified exploratory run.
- Review changes between pilot and final implementation before accepting the numeric design. Recompute/repeat affected calibration when changes alter execution, scoring, analysis, budgets, timing boundaries, locks, failure/retry behavior or measured costs. If only newly added, unused audit/report code changed the whole-package hash, record that provenance difference and the bounded applicability assessment; do not assert identical hashes or require an unexplained wholesale pilot rerun. Running the definitive pilot after all H1 implementation is committed avoids this ambiguity.
- The final pilot/design outputs must still satisfy the genuine numeric branch and resource gate; early implementation is not permission to fabricate a successful freeze. Protocol/docs/artifact generation must stay outside the execution digest only as the binding specification permits. New executable helpers/config-schema changes are not artifact exceptions.
