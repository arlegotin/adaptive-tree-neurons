# Remaining native qualification and production admission

This is an implementation contract for the remaining WP07/WP08 work. The
scientific populations, native recipes, semantic search supports and frozen-test
rules remain those in the approved design. No new method or study is admitted.

Keep three separate evidence levels:

1. **Implementation verification:** fixed direct-author, state, preprocessing and
   recipe fixtures under one source/test/lock identity. Seven profiles cover all
   fourteen families. A green profile verifies software only. No failed, skipped
   or zero-test result can supply that proof.
2. **Real workload qualification:** every required native anchor completes on its
   designated primary split with the full native procedure, correct row coverage,
   finite gradients/predictions, eligible native selection, closed state/recovery,
   independent prediction replay and measured resources. Exact acquisition/data
   bindings and support geometry checks remain mandatory. Software tests alone
   cannot qualify real workloads or wider/deeper configurations.
3. **Production candidate admission:** a frozen qualification registry, exact
   raw/compiled proposal, complete native model generation, fresh inference and
   independent primary V arithmetic agree. Only this companion evidence may make
   a model eligible in the paid search. Earlier engineering worker/model flags
   stay unchanged. Complete journal, cost and final protocol proofs are separate.

`native_verification_v2` implements level1. Its profile catalog fixes gated
P00/P01/P02/P05, ordinary P03/P04, RealMLP P06, TabM P07, trees P08–P11,
NODE P12 and simple P13 checks. The owned worker runs those complete files with
one numerical thread, disabled external pytest plugin/argument injection, an RSS
guard and no wall deadline. It binds all test/helper files, locks and current
scientific source before/after execution. Its externally committed inventory
and managed process/JUnit result can be reopened read-only. Skips block this
specific qualification; they are retained rather than silently called passes.
The original slice exercised the simple profile end to end. The later tree
profile correction explicitly binds its one pinned project overlay and all
owned parity outputs, overriding ambient tree-test controls; other profiles
explicitly clear those controls. The reader checks the same environment join.
Final-source execution of all seven profiles remains required after production
implementation. Earlier fixture receipts retain their own source and scope.

The first interface now supplies the
[joined anchor execution proof](native-anchor-execution.md). Its raw-acquisition,
complete-workload and production flags remain false. The registry interface is
still proposed:

```python
qualify_native_anchor(..., implementation_reference, generation_arguments,
                      immutable_generation_root, ...)
load_native_anchor_execution(reference, prepared_root=...,
                             expected_manifest_sha256=...,
                             expected_family=..., expected_anchor_id=...,
                             expected_dataset=...)
# Proposed; not implemented yet:
seal_native_qualification_registry(*, preparation_reference, profile_references,
                                  anchor_references, support_references,
                                  recovery_reference, output)
```

The registry must account for the fixed20anchors across six datasets, all seven
software profiles, and explicit variable-workload/support evidence. It must bind
current source/runtime/adapter locks, all actual configurations and source/row/
shape/resource proofs. Check raw acquisition byte hashes without reopening raw
target tables for modeling. A V value cannot determine technical inclusion.
Use the original fixed anchor inventory; unavailable mandatory anchors remain
unavailable and block a full-suite claim. Do not drop a slow or strong model.

All production WP09–WP11 code must still be complete and fixture-tested before
production primary searches. Final source qualification follows that revision.
Existing held-source executions remain useful development evidence and workload
forecasts; they cannot silently become current-source qualified models. No
compatibility migration has been admitted. Resource pressure permits declared
same-state/same-seed recovery and lower concurrency, with all earlier cost paid.

The future production callback must consume this registry, preserve the native
sampler preparation cost, and authenticate every candidate before passing its
score to selection. The final168primary-model seal must then bind the complete
paid journals, qualified model/validation proofs and global procedure before any
secondary-fold development or protected evaluation. The current implementation
does not yet provide that release capability. M3's negative Gate B stays closed;
an explicitly unchanged legacy practical reference is the remaining candidate.

The [prepared-data byte/source reader](prepared-data-lineage.md) now supplies
the recorded source/raw/sealed-byte consistency component. It hashes opaque
protected archives without decoding targets and grants no modeling authority.
The [managed preparation proof](data-preparation-execution.md) now adds trusted
current-source raw-table parsing/sealing, locked runtime/import identity and
owned process/output joins. Its reader hashes all sealed role archives without
decoding labels; it does not independently reconstruct their numerical content.
The complete registry must join this actual preparation lineage to native model
inputs. Earlier prepared/model assets do not migrate into the new source.

The [recorded native workload reader](native-training-observation.md) now covers
all fourteen families and raw process observations. It preserves each method's
native stopping/row policy and labels unexposed internal traces. All 57 combined
software checks passed at its recorded source, including complete native
procedures on synthetic role fixtures. Its workload/quality authority remains
false until this registry joins actual official-data executions, acquisition,
full support and recovery evidence under the final source.

The [full-size NODE recovery reader](native-recovery-qualification.md) adds a
managed numerical proof and independent comparison of saved reference/resumed
states, including optimizer, sampler and RNG. Its fixed 105-update engineering
horizon does not qualify native stopping or prediction quality. The complete
registry must join this capability under the same final source as the data,
software, anchors and support records. Other methods use a declared paid
identical-seed restart policy; this proof does not grant them persistent resume.

The [closed geometry reader](native-support-probes.md#reopening-a-closed-exercise)
now reopens a short probe's source/configuration/process/input/query records and
raw RSS summary through an externally committed inventory. It grants no full
native/workload/support qualification. The registry must consume these checked
records alongside complete native anchors rather than treating an unchecked
short-run result flag as authority.

[Full-geometry short probes](native-support-probes.md) now provide an explicit
engineering catalog and owned worker for wider/deeper support shapes. Only
synthetic ridge and128-unit ordinary-growth cases exercised the runner during
implementation. A short geometry result is not full native training or complete
support qualification; actual final-source workload/gradient/coverage evidence
and the registry remain required.

Resource forecasting must use retained artifact bytes, not parameter counts.
The completed Airfoil NODE snapshot contains32,705,993array bytes and a
24,465,520-byte manifest; its separate fit receipt is23,731,169bytes. These
include audit/training state. Account for the retained current/best training
states and transactions before admitting the larger searches. No completed
payload deletion, weakened model, shortened native recipe or changed evidence
retention is admitted by shared-input staging. Deployment reports must identify
an audit-inclusive bundle cost rather than assigning it to intrinsic prediction
arithmetic; a compact inference procedure needs its own qualification.
