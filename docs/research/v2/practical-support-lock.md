# Actual practical search support lock

`seal_practical_support_lock(output)` writes a fresh JSON file reference.
`load_practical_support_lock(reference)` checks its bytes and rebuilds the
complete current law independently. The lock contains all 84 dataset/family
declarations, 120 native anchors, the finite 29 simple configurations and native
quality budgets. Informed and random placement retain matching allowed factor
supports. No new ranges or methods are admitted.

The API reads existing semantic schemas, configuration declarations, source
references and the core runtime pin. It fits no model, draws no HPO samples and
reads no dataset. Metadata locking grants no native qualification, model
eligibility or protected authority.

Use the different identities consistently:

| Field | Meaning |
|---|---|
| Practical plan `support_lock_sha256` | SHA256 of the exact sealed support JSON file |
| Search plan `identity.support_sha256` | The corresponding dataset/family specification's `support_hash` |
| Production `runtime_sha256` | SHA256 of the qualified `locks/research-v2/core.json` |
| `source_sha256` | Current scientific Python source digest, separate from a Git commit or full package identity |

The file records current scientific source and core bytes plus each family's
existing source references. It does not embed the digest of *all* locks inside
itself, which would create a self-reference. The final qualification identity
will include the resulting support file externally.

All 75 affected checks passed at the recorded source. Immutable output, every
dataset/family, complete anchors, matched random support and the finite simple
space are checked. Even with a recomputed external file hash, changing source,
core, a family, anchor, range, unknown field or authority flag rejects. The
[receipt](WP08-practical-support-lock-receipt.json) retains exact commands and
an independently reopened temporary lock observation.

No production support file has been generated yet. Remaining production
implementation changes its source identity; generate the real lock only at the
final revision, before actual qualification and searches. A primary job factory
and qualified-search auditor must still bind this law, the full practical plan,
actual registry, source/runtime/data and declared HPO/model seeds. In particular,
RealMLP's native 63-bit HPO seed and the generic 32-bit library seed are distinct
fields. No selected model or global freeze follows from this component.
