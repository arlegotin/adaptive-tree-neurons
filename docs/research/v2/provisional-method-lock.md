# Pre-calibration method identity

WP09 requires an immutable provisional method and variance-only decision script
before any real calibration teachers are fit. This component binds that identity;
it does not authorize calibration, freeze a confirmation or release T labels.

Use the committed execution snapshot already enforced by the legacy source guard,
with a separate v2 record. Bind the claim kind, complete procedure configuration,
primary role mapping, any declared ordinary-control roles, the actual variance
decision source, fixed inference policy and byte-authenticated development/runtime/
support/decision references. Unknown outer fields fail. The owning procedure
validator still owns semantic configuration and workload qualification; a lock
cannot manufacture those qualifications from an opaque configuration dictionary.

Analysis constants are derived from design_v2: R2, useful2% margin,5% design
alternative, Student-t95%, teacher grid32..128 step8, variance-only16-to32
extension once and the fixed bootstrap/simulation laws. The old significance-
conditioned planning rule is not a configurable alternative here. C2 residual
capacity has its own role map; it cannot masquerade as C1 placement/pruning.
The calibration bootstrap seeds and power-simulation seed are derived from the
fixed calibration root and study/claim namespace when this identity is written,
before any calibration observations. They cannot be chosen from the outcomes.

Publication is immutable and returns an external file commitment only after the
record is fully written/fsynced. Loading requires that commitment and verifies
the complete payload/source/analysis/reference bindings. Documentation-only
commits may differ while execution bytes remain pinned. Changed source, ignored
execution overrides, changed references, self-rehashed payload edits and stale
external commitments fail. The returned payload is a copy, not mutable lock state.
The recorded checkout must also exist and contain the locked execution bytes;
a syntactically valid commit string is insufficient provenance.

Toy Git repositories test byte/source binding without fitting models, generating
calibration teachers or accessing protected labels. Their locks remain explicitly
provisional and cannot be passed to either protected evaluator. Full readiness,
calibration lineage/resource authentication, root commitment, confirmation/v2,
grouped/temporal protected access and protocol freeze remain separate WP09/WP10
implementation requirements before any production HPO/calibration.

The separate [seed commitment](confirmation-seed-commitment.md) can bind a fresh
root to this chosen identity on fixtures. It preserves the distinction between
known seed exclusions and complete generated-teacher independence; it also
grants no protected access.

Verification retained144 passing affected checks on the initial implementation,
then two failing checkout-provenance regressions, followed by41 passing focused
checks on the corrected source. This is not a final144-check rerun or a complete
repository pass. Legacy protected-evaluator tests use disposable sentinel data;
no production protected observations or real calibration teachers were accessed.


The policy now names the implemented secondary confidence-region construction
and strict endpoint convention explicitly, replacing the earlier unresolved
placeholder. The `secondary_bounds` binding authenticates primary_v2.py along
with the method lock, variance decision and seed derivation. Loading rejects a
self-rehashed endpoint change and any changed secondary-inference bytes. This
strengthens the provisional identity; all calibration/protected authority remains
false. It does not turn earlier provisional fixtures into a final protocol.
