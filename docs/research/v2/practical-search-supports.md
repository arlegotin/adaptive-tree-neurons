# Finite practical search supports

This Task 8 slice translates the spec's fixed semantic ranges into existing v2
adapter configurations. It does not run HPO, read labels, qualify a workload or
publish a final adapter/support lock. Source/configuration identity, full native
qualification, production workers and the final protocol remain prerequisites.

`research/search_supports_v2.py` exposes `family_search_spec(family,schema)`
and `compile_search_draw(family,schema,draw)`. Each family record includes its
native anchors, search type, finite support, attempt limit and explicit lack of
execution/quality authority. Raw generic TPE draws contain only atomic parameters;
the compiler validates every value and produces an exact existing adapter schema.
The raw draw, compiled configuration and all ignored conditional coordinates must
remain visible in the eventual paid trial record. No duplicate or invalid draw
is silently replaced to obtain 32 successful configurations.

P00/P01 share every range and current direction/treatment; only placement differs.
P02 has both ordinary parameter brackets. P05 has all four static variants.
P03 injects the published MLP-D anchor plus the historical width64/LR.005/WD0
coordinate under P03's native preprocessing/stopping; that second anchor is not
an exact replay of the historical recipe. P04 retains the complete ResNet-D
anchor, including its exceptional .25 hidden dropout. P07 has both plain and
piecewise-embedding native anchors. Native anchors outside generic ranges remain
explicit and do not expand the later generic support.

P06 uses its already pinned official regression sampler/schedule, not generic
TPE. Its official anchor is first; materialized native suggestions and preparation
cost are retained. P13 exhausts exactly 29 configurations, mean first. Every other
family uses the spec's single bounded TPE support with native anchors first and
at most 32 total paid attempts, including anchors/failures. The controller already
treats anchors outside the surrogate; that policy is unchanged.

Zero-or-log regularization and zero-or-uniform dropout use explicit categorical
mode plus value coordinates. Inactive value coordinates are still recorded and
charged; they are not applied to the model. Uniform-width MLP depth/width become
`hidden_dims`; TabM embedding coordinates apply only to the piecewise variant.
This is a fixed declared parameterization of the permitted ranges, not adaptive
range invention or an extra trial budget. RealMLP's own probabilities/dependencies
remain in its native sampler. The complete support and translation rule must be
hash-locked before primary searches and remain unchanged across secondary splits.

The implementation passed 26 initial native-schema/range/anchor checks after
26 missing-component RED cases. The expanded verification passed 113 checks in
35.61 s, including the existing TPE/controller, official RealMLP sampler and
gated-core checks. A retained artificial feature-schema descriptor covers all
14 families and 20 anchors; it creates no observations, model fits or validation
selection. P13 retains 29 configurations. No final qualified support lock or
production raw-draw/worker/V-score bridge is supplied by this component. See
[the receipt](WP08-family-search-supports-receipt.json).
