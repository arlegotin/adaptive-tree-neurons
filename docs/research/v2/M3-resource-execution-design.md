# M3 qualification and live execution

This is the implementation design for the fixed M3 study, before generating its
scientific teachers. Native workers and the complete3089-entry graph are tested;
public scientific execution is still unadmitted. The current code/receipts state
which parts below are implemented. This document grants no protected access.

Use the exact source/runtime/configuration-bound graph and preserve every nominal
case. The initial tranche has8teachers/R2,160final fits,1040short probe entries
and16parents. The one conditional tranche has the same maxima. The strong common
recipe and extension rule are in M3-development-recipe.md. There is no wall-time
quality deadline; the8000/300update horizons are the scientific treatments.

Qualification uses an independent engineering seed namespace:
`seed64(2026101801, study_id, 'engineering-resource-only', 'primary', 'teacher-0', role)`.
Parent and fresh optimizer seeds use the separate labeled32-bit derivation with
collision recording. Those are not scientific M3 teacher seeds. The construction
is fixed before its outcomes; there is no favorable-teacher replacement or method
retuning from qualification quality. Native data generation remains the real
primary family at F2306/G577/V577/E65536 so its preprocessing/reference/prediction
costs and shapes are exercised. Its resulting teacher is engineering development
information and excluded from any future protected namespace.

The qualification graph takes the complete first-group native spine, with those
engineering seeds substituted in every relevant payload: data, parent, score,
four placements, four local-model checks,65probes including keep, one G structural
choice, ten final fits and ten evaluations. That is97native queue entries, not
97independent problems. All ten final fits retain the full8000fixed horizon; all
probes retain300; parent retains the native8000ceiling/G25/patience20. Maximum
optimization is107500updates. Ineligible nominal candidates stay recorded.

An additional160explicit synthetic metric fixtures exercise the full extension
decision input shape, followed by its one decision job. These fixtures write no
model and create no scientific teacher. Their risks are fixed at1, so the decision
returns no extension. This is the same kind of transparent decision fixture used
in the earlier M2 resource qualification. It is not a native predictive result.
The full qualification graph therefore has258entries and35distinct resource
classes. Model/gradient/stopping/role coverage must come from the real native
spine, rather than synthetic fixture status. Qualification records distinguish
native workload evidence from the synthetic decision.

The35classes are data, parent, score, short selection, extension decision;
four placement and four local-model variants; keep versus singleton probes;
and ten final-fit/ten evaluation roles. The exact source-fixed architecture/data
contract permits sharing a shape/treatment profile across teacher IDs. Requested
count16 is the maximum live gate count; reduced common eligibility is cheaper in
that dimension, but must remain explicit. Retained parameters, rows, dtypes,
full-data coverage and complete eligible checkpoints must match the qualified
native topology. No hard F subsampling or shortened baseline is admitted.

Before native qualification: produce a fresh real CPU backend receipt under the
final executable revision, expand/lock its target and qualification manifests,
verify sufficient live resources and pin a held checkout. Do not edit that
checkout while it runs. MAIN may continue independent downstream work. Every
qualification profile binds the full source digest, runtime/receipt identity,
job hash, actual terminal status, executed updates, retained file inventory,
containing queue clock, own-process lifetime peak RSS and largest checkpoint
transaction estimate. Do not add nested handler/queue/process clocks.

Resource forecasts use authenticated completed profiles for every class. A
failed or capped model cannot qualify an eligible native fitting workload.
For parent fitting extrapolate the observed execution to its8000ceiling. For
warm/probe history storage also bound the inherited selected-parent prefix up to
8000absolute updates; fresh ordinary models do not inherit that history. Log
sample counts and distinguish median/upper extrapolations from measured
population quantiles. Full initial and conditional counts, raw disk forecast,
retry reserve, maximum checkpoint transaction, peak memory and containing clock
remain visible. Forecasts describe possible time, without enforcing a time cap.

Admission is for the next complete job plus a rolling same-seed retry reserve,
checkpoint transaction and free-space margin. Default own-worker RSS guard is
3GiB, based on the completed sub1GiB selector workload; actual qualified peak and
live available-memory proxy determine readiness, without a20GiBfree-RAM floor.
The initial engineering admission can use a conservative4GiBavailable-memory
proxy and2GiBfree-disk floor. Record that the macOS free/inactive/speculative
page sum is a heuristic, not a reservation. Preserve all original horizons and
queue cases when other applications consume resources.

When a whole job cannot fit, leave the immutable queue at its real position and
report `paused_before_job`. This is an operational pause, not user cancellation.
Resume with the same source/configuration/queue and seed; no losing trial gets a
new seed. Retain all interruption/failure time. Existing queue policy permits
one deterministic same-seed infrastructure retry and no numerical-failure retry.
Native best/current checkpoints remain recoverable under their source identity.
A pending implementation must not claim per-job checkpoint resume if it actually
restarts the deterministic same-seed fork.

If full raw archive size exceeds free disk, disclose that forecast. The qualified
byte-preserving APFS operator can compress completed logs while the producer is
inactive and the required exclusive lease is held, then verify every original
logical hash/size/result marker before resuming the unchanged queue. It does not
remove losing cases or alter evidence paths. Never compress active checkpoint
histories concurrently with readers. Temporary copies and receipts stay outside
protected inventories. The2a129c78operator/0d241cecqualification are already
qualified on this platform. Its native file-flag operations need the escalated
execution context: the sandbox copy silently produced size0/flags0 and was
safely rejected before publication. The retained disposable native proof restores
identical bytes with UF_COMPRESSED. Do not relax that guard.

Public `run --config M3-joint.json` and its admission validator are now
implemented. Scientific execution remains blocked until actual final-source
profiles are complete and authenticated. `qualify --config M3-joint.json` routes
to this engineering spine, separately from the14-family transfer qualifier.
Neither command may open protected T. The supervised launch operator is
`docs/research/v2/scripts/run_m3_qualification.py`; it preserves the held source,
records process startup/exit/RSS, retains every attempt and accepts explicit
same-identity `--resume`. It has no wall deadline. It does not grant admission
merely because its child exited successfully.
Final Gate B needs fresh primary evidence and complete-cost reporting beyond the
already passed four-base small-oracle prediction screen. No M3 scientific
teacher has been generated at the time this design was written.

publication after every step while retaining all raw update events. It applies
