# B0: bounded native-backbone development screen

This is a WP07 primary-synthetic native-baseline diagnostic within the approved
comparison supports, not an M3 extension, replacement placement estimator or
confirmation. M3/Gate B remains negative. The transfer anchor survey also
favored existing baselines on all five observational tasks, but its single
one-layer coordinate does not establish a competent one-layer family ceiling.

The question is whether a specified ordinary one-layer family remains materially
behind native stronger backbones on the primary synthetic population. A positive
screen would justify measuring residual conditional structure before deciding
whether the already-described M6 residual branch is admissible. It would not
admit M6/C2 automatically, establish gated capacity value or change P00/P01.

The one-layer grid below uses native quantile preprocessing. A backbone win
against that grid does not establish that the F-standardized competent
ordinary continuation used in M3 has reached its ceiling. Before any M6
admission, the separately fixed follow-up must include that ordinary treatment
on the same B0 data, as well as the required residual-structure measurement.
This safeguard is declared before B0 teacher creation; it adds no B0 fits and
does not reopen M3 placement selection.

Use exactly four fresh development teachers, two paired training repetitions
and nine fixed configurations:72 native fits, with no effect-triggered expansion
or additional tuning. Generate the existing primary d16 teacher through
`prepare_data_artifact`/`make_from_config`, retaining every resolved generator
default, coefficient, normalizer and actual array. F2306/G577/V577, sigma.1 and
independent exploratory E65536 match the existing primary coordinate. E remains
development information. No protected T or confirmation root is created.

The one-layer family contains the published historical coordinate under native
P03 preprocessing ([64], ReLU, dropout0, LR.005, WD0) and four width-only variants
[64], [128], [256], [512] under the published native MLP-D optimization recipe:
ReLU, dropout.1, AdamW LR.001/WD.01, batch128, no scheduler, maximum1000epochs,
G each epoch/patience20/best-G restoration, F-fitted native quantile features and
target scaling. These are finite supported configurations, not a universal
one-layer optimum. The stronger family contains the complete published MLP-D,
ResNet-D, RealMLP-TD and embedded TabM native anchors already specified in the
main design. Preserve all their own native preprocessing, losses, embeddings,
initialization, schedules and stopping. Each configuration is fixed before
outcomes; no HPO or seed selection is performed.

Use root2026101801 and the canonical v2 hash derivation with matrix label`B0`.
Teacher, reference, development-data and E seeds use separate labeled namespaces
and omit method/repetition. Each teacher/repeat has one paired32-bit fit seed
shared intentionally across all nine configurations; independent labels use
the existing collision-counter rule. Record and check new teacher IDs/seeds
against the known exclusion registry, then extend that registry with these
development identities. Do not regenerate an unfavorable teacher or replace a
numerically failed seed. Parent-training randomization is paired by seed label,
not a claim of equal parameter draws across different architectures.

Workers receive F/G labels and V features only. An independent coordinator
retains V/E labels and evaluates closed retained models in original units.
Feature-only post-fit prediction can additionally retain F/G predictions for
later residual diagnostics; it performs no weight updates. Retain and check
row/group IDs, raw array hashes, complete native stopping/coverage/gradient
records and closed-model predictions. E inference uses fixed1024-row chunks;
V replay uses each adapter's original prediction treatment and checks the
saved worker vector. Future residual fitting needs a separately fixed manifest.

Within each family, select its complete configuration on V normalized MSE using
the existing numerical tolerance and earliest-configuration tie rule. Select
neither seeds nor teachers. Report every configuration and both repeats, plus
the two V-selected family procedures. Average repeat risks within teacher
before computing teacher log-risk ratios. Comparisons with retained M3 means
are descriptive across different teachers/treatments and are never paired.
Report costs for all five one-layer or four backbone fits in each portfolio;
their quality comparison is not an equal-total-cost result.

A named screening trigger is at least5% lower E risk for the V-selected
backbone family on at least three of four teacher means. This is a development
branch rule, not a significance test or confirmed population margin. If it
passes, separately preregister the residual-structure measurement required by
M6. If it fails, record the family-ceiling screen as negative/inconclusive and
do not add configurations or teachers. In either case, no claim that gates
improve strong parents follows from this diagnostic.

Before fitting, serialize the exact72-case manifest, source/adapter/environment
identities and all seeds. Keep its producer source immutable while other work
continues. Use one new native worker at a time with no wall deadline and a
4GiB owned-root RSS guard, in addition to the separately held serial NODE
anchor run. Require at least8GiB live free/inactive/speculative memory proxy
and4GiB free disk before each fit; these are admission heuristics, not resource
guarantees. Forecast retained state/transaction bytes before admission using
available native anchor measurements. Defer the unchanged queue under resource
pressure. A deterministic same-request/seed restart after an infrastructure
failure is allowed once, with prior evidence/cost retained; no weaker recipe
or hidden F subsampling is permitted. All terminal statuses stay visible.

This document precedes teacher creation and outcome access. Its numerical
screen, finite configurations, labeling and resource policy are part of the
run manifest. Native implementation qualification and all final production
WP08–WP11 source/freeze requirements retain their existing scope. This small
development screen cannot qualify the full mandatory practical suite.
