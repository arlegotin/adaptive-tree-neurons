# Native qualification registry

The registry connects existing checked components. It does not run training,
choose a model from validation scores or authorize protected evaluation.

```python
seal_native_qualification_registry(
    *, preparation_reference, prepared_roots, profile_references,
    anchor_references, support_references, recovery_reference, output)
load_native_qualification_registry(reference)
```

Coverage is fixed independently of outcomes: seven software profiles, twenty
native anchors on each of six official datasets (120 coordinates), 43 declared
support geometries per dataset (258 coordinates), official managed preparation
and the full-size NODE recovery proof. Missing, duplicate or unknown coordinates
fail before component readers. An unavailable mandatory comparison blocks a
complete registry; it never receives an invented prediction loss.

Every software profile must have the same current source/test/lock identity.
Each native anchor must join its software proof, exact native configuration,
managed fit, full recorded workload, independent closed prediction replay and
primary validation arithmetic. The workload must belong to that same generation;
another valid model record cannot supply it. Validation rank does not determine
technical inclusion. Short support exercises remain short geometry evidence,
with no claim to test every Cartesian hyperparameter combination. Every future
search candidate still requires its own full native-workload check.

`prepared_roots` explicitly identifies six working dataset directories outside
all immutable proof roots. Their manifests and every sealed role archive must
match the authenticated preparation bytes, including opaque protected archives.
Protected labels are hashed without decoding. The existing role coordinator
appends access records in the working directories. It therefore leaves the
closed preparation inventory unchanged. This explicit byte join replaces the
initial proposed use of the immutable preparation directory as a training root;
no split, table, target, transform or trained state is migrated or regenerated.

Reopening the registry reopens all prerequisites, rechecks current identities and
recomputes its body. Original engineering worker/model flags stay unchanged.
Only a complete actual registry can provide the companion technical capability
for later candidate admission. Its quality-eligibility, HPO-journal and protected
access flags remain false. Non-NODE recovery is a paid identical-seed restart;
NODE has the separate checkpoint-resume proof. All source changes invalidate
earlier live qualification identities.

Verification uses real official preparation and small native model records,
plus deliberately incomplete coverage. It includes an actual permitted access
that leaves preparation unchanged, opaque-role tampering, a prohibited working
root alias and two different valid native executions. These tests do not
construct a fake complete qualified registry. The full final-source bundle is
unrun: all remaining production implementation and its review still precede
actual qualification and primary searches. The
[component receipt](WP07-native-qualification-registry-receipt.json) records
executed checks, failures and the optional overlay boundary. Gate D remains
unpassed until the actual complete bundle succeeds.
