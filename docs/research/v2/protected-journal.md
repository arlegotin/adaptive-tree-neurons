# Protected ownership and journal component

The new preparation and inspection entries load the genuine final practical
protocol before any study, owner or data I/O. The protocol still requires actual
complete model/native/global, pre-T cost and production-readiness gates.
Complete-qualified public success remains unrun. Existing primary and secondary
role guards remain unchanged.

Protected ownership uses the official dataset name, raw-file SHA-256 and target.
It survives a new study name, source revision or preparation timestamp. Each
asset belongs to one protocol digest, study directory and random genesis. A
byte-identical protocol copy can resume the retained original directory; a new
directory cannot reset its history. Public entries use one fixed workspace owner
archive. Keep that archive with the release bundle. This is workspace/bundle
governance, not isolation from a person who controls the operating system.

The study writes its immutable binding and initial journal before claiming
assets. Claims are locked in deterministic order, with every conflict checked
before any missing claim is published. An interrupted partial claim transaction
retains its claims and can resume only the same binding. Missing or partial
history blocks recovery; it is never recreated as a fresh evaluation.

Each event commits the complete binding, actor, sequence and previous event.
A separate immutable witness in the owner archive detects truncation to an
otherwise valid journal prefix. Symlinked storage and changed committed files
are rejected. A witness/journal transaction interrupted between writes remains
explicitly incomplete and blocks automatic continuation. No deletion or reset
is an accepted recovery.

The metadata state machine requires all frozen query commits before the single
label stage. It retains failed attempts, known consumed time and unknown cost
separately. Resource interruption resumes the same query/state; a dependency
failure permits one deterministic same-seed rerun. Numerical failure or lost
outcome blocks completion. A committed query cannot silently run again.

These private state-machine fixtures **do not authenticate numerical predictions
or authorize any data access**, even when their symbolic phase is
`labels_started` or `metrics_committed`. The actual finite/aligned prediction
validator, native query worker and label reader are the next implementation.
The preparation/inspection return values deliberately retain false native,
protected-access and T-access flags. A genuine protocol by itself also grants
no label access.
