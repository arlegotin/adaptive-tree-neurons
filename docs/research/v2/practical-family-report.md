# Practical families in the canonical report

`practical_family_report_record` projects the complete paired comparison result
into the canonical renderer's optional family records. Every P01–P13 hypothesis
remains visible, including unavailable families. It preserves strict adjusted
tests and open versus closed lower endpoints, using the existing common region
validation. An open endpoint at the useful margin does not establish a numeric
effect-size gap above that margin.

This construction has its own explicit type. Its units are held-out groups or
days **within the five fixed tasks**. The report lists each task's actual count,
the Bike calendar block length, the number of bootstrap draws and the declared
dependence assumptions. It neither pools clusters into one sample size nor
labels five datasets as independent teachers. CCPP exchangeability and the small
Parkinsons subject count remain visible.

Projection checks the complete hypothesis inventory and shared resampling
metadata against every family and the champion. Rendering rejects inconsistent
counts, assumptions, probabilities, rejection flags and confidence endpoints.
Supplied arithmetic remains distinct from authenticating models, V choices,
raw predictions, a frozen protocol or protected access.

The affected six-module suite passed **112 checks in 1.99 seconds**, following
14 missing-interface failures. A separate capture compared the old and new
renderers: ordinary and teacher-family reports were byte-identical, and the new
practical report was byte-stable. The [receipt](WP10-practical-family-report-receipt.json)
retains the old renderer, synthetic family record, reports, command and source.
No native fitting, real labels or T were involved.

The full artifact auditor, protected evaluator, global practical protocol and
production queue/readiness remain unfinished. Renderer validation does not
grant scientific eligibility or close those stages.
