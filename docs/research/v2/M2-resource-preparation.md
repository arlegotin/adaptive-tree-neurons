# M2 resource forecast preparation

This is implemented planning arithmetic, not native workload qualification or
production admission. Public M2 execution stays disabled. No native resource
profile or actual time/disk forecast has been generated by this component.
Tests use explicitly labeled analytic software profiles.

The complete bounded graph contains3,853 jobs and10,908,000 nominal/conditional
maximum optimization updates: parents768,000; M2a6,400,000; M2b156,000;
M2c576,000; nominal M2d2,368,000; M2e640,000. Unavailable nominal subsets and
nonadmitted conditions remain in this conservative ceiling. They are not claimed
as executed work. The graph maps to53 shape/treatment workload classes, including
22fit and12evaluator classes. Actual instance/repeat seeds share a class; parent
recipe, ordinary94/95 width, gate count, stream treatment, fixed versus patience
policy, horizons/prefixes and evaluator topology remain explicit.

The preparation helper requires a source/runtime/class-matched eligible profile
for every class. It projects observed whole-job time and retained bytes to full
update ceilings, using the maximum of one and the ceiling/executed ratio. It
reports median observed projected time and a1.5x slowest observed envelope.
These are uncalibrated projections, not promised P50/P90 completion quantiles.
Retained bytes use25% headroom, a checkpoint-transaction allowance and64KiB
publication allowance per job. Peak own-process RSS and the largest transaction
must fit the declared envelope. No source/runtime/profile outcome is invented by
the helper. Native profile-file/artifact authentication is a separate pending
prerequisite before these inputs can support production admission.

Remaining storage credits only whole terminal jobs. Partial/interrupted work
retains a full allocation; its already written bytes still occupy real disk.
The largest untouched job supplies one rolling retry reserve. Attempted IDs and
latest status IDs must match; status-less claims cannot erase that reserve.
Forecast and source/runtime/queue identities are bound. Physical shared costs,
standalone attribution and worker-loss upper bounds remain separate.

The public dispatcher, native profile collection/authentication and live
resource checks for M2 are still pending. Future launch/resume must use those
checked measurements and current free space under the queue lease. Inadequate
space pauses the unchanged queue; it does not authorize changing seeds, data,
comparators or update ceilings. The current M1 experiment remains pinned to its
own previously admitted source and resource contract.

Before native resource qualification, the queue's per-job timer was expanded to
include identity checks, dependency file authentication, running-record
publication and result publication. The current attempt's preparation_ns is
retained alongside cumulative elapsed_ns; prior failed preparation stays paid.
An injected50ms dependency read was absent in the RED test and included after the
change. The39affected checks passed in12.98s. This changes the new queue's cost
boundary, with no M2 scientific run yet; it does not relabel old timer receipts.

Initial/resume inventory authentication, final ledger publication and process

Class forecasts from job observations alone are not a whole-procedure cost claim.
Source-bound native profile/admission work must retain that overhead explicitly;
