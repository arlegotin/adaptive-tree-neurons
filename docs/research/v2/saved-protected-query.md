# Saved-state protected-feature query primitives

The public preflight loads the genuine final protocol and owner journal before
compiling a query. It accepts only an available frozen query at the prediction
stage and a fresh exact query/attempt output location. It creates no output,
starts no worker and opens no query arrays. Its draft is not permission to
bypass the future owned coordinator or journal reservation.

The private forward core verifies the original T-feature role, query identity,
full saved snapshot inventory, selected recipe and feature schema before method
imports. Query archives contain only finite float64 raw features, unique int64
row IDs, int64 group IDs and, for temporal queries, increasing actual timestamps.
Labels and extra fields are rejected. Source/model/feature commitments are
checked again after inference.

The core restores the retained model and its F-fitted preprocessing through the
method-specific loader. It never calls `fit`, changes a training seed or refits
on new roles. The logical 63-bit job seed remains an identity; loaders restore
their actual saved native configuration and seed. Numerical input precision and
native output dtype are preserved. The existing V worker and data-role guards
remain unchanged; no T archive is renamed to V.

A prediction archive is published only after complete serialization and fsync,
using exclusive publication. A disk-full interruption leaves explicit pending
bytes and failure evidence, not a partial final prediction. Failures do not
produce imputed losses or silently change the model.

The final ten-module command passed **205 checks in 107.81 seconds**, with four
retained warnings from the existing small NODE fixtures and its vendor API.
Fresh-process gated and NODE fixtures reproduce their saved predictions and IDs
exactly. Nonconstant ridge and spline fixtures retain their fitted geometry,
unknown-category handling, float64 predictions and temporal identities. This is
software evidence, not a predictive comparison. The
[receipt](WP10-protected-query-receipt.json) retains initial failures, a test-helper
import-path correction and the disk-full publication defect/fix.

The separate retained capture fits two known local P13 fixtures, then restores
and predicts 37 feature rows each, including an unseen category. Both outputs
match the original models exactly; the spline case also preserves timestamps.
The saved native seed is17 while the logical query seed exceeds32bits. Neither
case imports Torch or another tracked heavy model namespace. The actual public
false-qualification route rejects before creating output. No benchmark model
was fitted, no benchmark labels were read and no actual protected inference ran.

These are **primitives**, not a completed protected reader. Their private
outputs grant no native qualification or access authority. The owned coordinator
and cold-worker handshake must still reserve and bind each actual query before
feature access, validate numerical commits against the owner journal, and enforce
the final label barrier. Actual full-qualified public success, raw/model/access
audit, deployment and whole-cost completion, CLI/readiness and final review remain
unfinished before final-source qualification and production searches.
