# Binding the declaration to caller and worker

The explicit `research/v2-primary-program-episode-request` subtype requires both
an immutable practical procedure reference and the measured resource reference.
Its procedure remains part of the job/recovery identity. Older ungated/resource
engineering requests retain their own schemas and reject this extra field.
No schema can gain a caller-written production-ready flag.

The caller forwards that reference through actual qualification-first preflight.
Preflight validates the declared semantics before outputs and protects the
procedure file with the other inputs. The cold worker also starts with actual
qualification, then validates the same procedure against its exact plan/support
before creating its worker output or preparing a fit. Existing source, sampler,
paid-attempt, recovery and resource checks remain in place.

The affected seven-module suite passed **120 checks in 7.03 seconds**. Initial
verification retained four missing-interface failures and seven already-valid
negative checks. A real cold program worker rejected false qualification before
reading a procedure, plan or role array, and created no model/search output.
This is a negative software execution, not a completed qualified public success.
The [receipt](WP09-procedure-worker-binding-receipt.json) records source, commands
and that raw owned process evidence.

This request binding does not complete the production program queue, physical
whole-cost audit, readiness, post-search freeze or secondary/protected evaluator.
The [serial primary program](primary-program.md) now requires this subtype.
Complete-qualified execution/readiness and CLI dispatch remain pending. Legacy
component requests are not production authorization. No native result or
held-source job changes.
