# Owned original-snapshot measurement

The new measurement leaf loads a saved model from its original absolute
snapshot path. It checks the complete inventory, selected metadata, family and
feature schema; it copies or relocates no model. The original saved native seed
and configuration drive loading. Logical job seeds do not initialize a model.

Only standard-library code precedes the cooperative ownership handshake. An
unowned invocation fails before reading its request/features or importing a
method. After admission, it validates a label-free1,024-row float32 workload,
explicit workload IDs and F-derivation metadata before method import. The
production controller must still authenticate that derivation against the
actual frozen F role; metadata flags cannot supply it.

For batches1 and1,024, the leaf records common numeric imports, frame creation,
method imports, model loading, first prediction, three warmups and32 resident
calls separately. It checks finite original-unit outputs and bitwise repeated
predictions, including native preprocessing. Full process wall time includes
the measurement workload; it is not a single cold prediction latency.

The read-only inspector checks actual ownership, normal body closure, request/
model/query bytes, saved seed, input precision, exact field/sample inventories
and nested clocks. Consistently rehashed but contradictory closure, clock,
seed, unknown-field or precision records fail. It never fits or predicts again.

All native-model, F-role, dedicated-timing, precision-equivalence and cost-claim
flags remain false in these primitives. Actual qualified model/controller and
paired-block/cost gates are separate. Contended measurements do not establish
dedicated timing. Native-quality queries use native float64 features; formal
efficiency claims cannot silently use mismatched float32 quality evidence.
The mandatory quality comparison remains unchanged.

Existing engineering deployment request/path/workload guards remain intact.
The new primitive still needs the production controller, complete observed
caller/physical costs and final report/readiness integration before use in
production. There is no training wall-time cap, model/batch reduction or20GiB
free-memory requirement introduced here.
